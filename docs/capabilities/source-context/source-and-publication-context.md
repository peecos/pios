## Cross-cutting interpretation

- Current PIOS is the whole personal information operating-system framework, not a historical app catalogue or only its storage layer.
- Core-contract membership, PIOS-system membership, physical placement, and state treatment are separate classifications.
- Derived or rebuildable state is not automatically outside Core, PIOS, or a PIOS distribution.
- Historical pillars are not the current five Core zones.
- A proposal is a governed decision object; a notification or Update is a possible presentation of it.
- A schema declaration is not evidence of a reachable, tested, deployed, or available capability.
- Personal glossary terms, owner-confirmed organizing labels, AI-assisted labels, Roles, and Modes carry different authority and meaning; shared UI presentation does not merge them.
- Cotton governs contextual organization but is not itself a database schema, fixed taxonomy, or app-specific feature catalogue.

## Restricted-evidence policy

Restricted evidence may corroborate, contradict, or leave a public capability claim unresolved. Public documents record only the evidence maturity and publication disposition needed to interpret the CRD. Unique private requirements and implementation details remain outside this repository until explicitly cleared.

## Non-normative source sequencing

The historical source grouped behavior into application-oriented pillars. The capability library instead decomposes that material by independently meaningful outcome. This extraction order is project workflow and does not prescribe implementation order.
